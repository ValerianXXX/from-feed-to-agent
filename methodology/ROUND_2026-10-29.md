# October 29, 2026: task, evidence and export pilot

This protocol is frozen before new research queries. It preserves the August study and the October 27 pilot. The new prompts occupy all 24 historical cells (three categories, four stages, two tasks per cell). They are new public prompts, not reconstructions of unavailable private prompts. The six pilot tasks cover inspiration in every category and one comparison, validation or shortlist task per category. Each has one initial attempt on each of four historical surfaces: 24 planned slots.

## Scope and stopping rules

- Use only existing browser access, synthetic shopping needs and public product specifications. The named products are fixed examples, not a claim to test the newest product generation. No purchase, posts, messages, new paid service, personal data, access-gate bypass or account changes.
- Submit each exact frozen prompt once, in catalog order on each available surface. No repair prompts, supplemental searches or retries are part of the initial-attempt result. At most 24 submitted research queries, 120 seconds to the first stable usable result or visible timeout per attempt. Observation windows include UI collection overhead; first-useful latency stays null unless directly timed.
- Check access once per surface. A visible session-wide verification challenge or age gate can block all six planned slots, with the same explicit preflight reference. Those are six unavailable slots, not six submitted failures. Do not infer an entire platform's accessibility from this session.
- Preserve the search-page boundary for YouTube and TikTok: result titles, snippets and public links only. Do not infer watched-video content, answer correctness or task completion. This restriction is a historical method choice and limits cross-surface comparisons.
- Google AI Mode and ChatGPT receive the same prompt. Account state, browser, visible model and product build are recorded. Undisclosed versions and attributable subscription cost remain null. No API substitute is silently labeled as the consumer interface.
- This is one bounded pilot. A second round, broader task set or changed platform needs a separately frozen protocol; do not turn successful retries into initial-attempt results. A formal repeat should preserve the historical separation of at least 72 hours.

## Frozen truth and criteria

The [catalog](../public/rounds/2026-10-29/tasks.json) contains prompts, source IDs, expected facts, decision criteria and pilot selection. Official Apple, Sony and Roborock sources were checked on October 29, 2026. The Roborock manual uses printed page numbers 8-9 and 12. The corpus checks product suitability boundaries; it is not a complete shopping recommendation or diving safety assessment.

Every required fact receives CORRECT, INCORRECT, MISSING, UNCHECKABLE or UNSCORED. A checked fact needs an original-response location and retained official source IDs matching its frozen reference. Every source distinguishes SURFACE discovery from an analyst REFERENCE_CHECK; the latter can verify facts but cannot earn discovery, evidence-retention or completion credit for the platform. Count an omitted requested fact as missing; do not remove it from the denominator. Record the three task criteria separately. Correctly limiting an unsupported claim is part of the task, not an automatic failure.

The collector derives completion only when a visible answer and self-contained deliverable satisfy all required facts and criteria. Relevant search results, a fluent answer, a correct decision and a saved handoff remain separate outcomes. An actual platform export needs a relative file path, media type, byte count, SHA-256 and save time; the collector checks the file. An analyst transcription is not a platform export. Hashes establish file integrity, not the truth of human observations or export provenance.

## Observation, coding and review

The V2 collector separates raw redacted observations, per-fact coding and adjudication into an append-only hash chain. A single-writer lock prevents cooperative concurrent writes. It detects changed catalog content, duplicates, edited records and partial tails. It does not provide multi-host transactional storage, cryptographic authorship or automatic truth checking. Keep backups; stop and preserve a damaged ledger rather than rewriting history.

Coding records include a stable coder ID and kind. A second coder can append their own independent vector without replacing the first. Conflicts remain visible and withhold aggregate completion until an explicit adjudication records the reason and both coder IDs. A second pass by the same agent is not independent human validation. No independent second coder has been assigned at protocol freeze.

Public rows contain original redacted descriptions, public source URLs and outcome codes. Private session URLs, account names, screenshots with account information and raw full copyrighted responses must stay outside the repository. The release scan includes JSONL. Summaries are derived, replaceable artifacts; the ledger and frozen task catalog are the source of truth.

## Run the collector

Node 22.13+; no new packages or service required. From the repository root:

```sh
node scripts/research-collect.mjs prepare public/rounds/2026-10-29/tasks.json /absolute/ledger.jsonl
node scripts/research-collect.mjs append public/rounds/2026-10-29/tasks.json /absolute/ledger.jsonl /absolute/observation-event.json
node scripts/research-collect.mjs append public/rounds/2026-10-29/tasks.json /absolute/ledger.jsonl /absolute/coding-event.json
node scripts/research-collect.mjs summarize public/rounds/2026-10-29/tasks.json /absolute/ledger.jsonl
pnpm test:round
```

Use OBSERVATION, CODING and ADJUDICATION payloads as defined in `scripts/research-ledger.mjs`; tests provide clearly marked unit fixtures. Existing rounds use their original collector and remain readable. Never mix V1 rows into a V2 ledger or overwrite an initial attempt. If a writer crashes and leaves `.lock`, confirm that collector is stopped before moving the lock aside manually. If a partial line exists, preserve the original and document any recovery in a new ledger; the CLI does not truncate it.

The evaluation design draws on [OpenAI's task-specific evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices) and [skills evaluation guidance](https://developers.openai.com/blog/eval-skills), checked October 29. No external source code or new evaluation service was adopted. These references inform the method; they are not findings about the tested platforms.
