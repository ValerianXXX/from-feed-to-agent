## Access, environment and collection

- Desktop browser, English queries, U.S. target, one existing browser session. Record each surface's visible login state and model label; undisclosed model/build versions stay null.
- Existing ChatGPT account access is available; use a new temporary chat when supported. Do not read old conversations. Google/YouTube may be signed out. Preserve these differences in each observation.
- Submit the exact frozen prompt once. Do not prompt-engineer a failed response into a successful initial attempt. No paid account, CAPTCHA bypass, login consent, purchases, posts, account changes or real personal data.
- Record the first stable response or visible failure. First-useful latency is null unless directly timed. Elapsed observation wall time includes UI/tool overhead and is not model-only latency. Stop each initial attempt after 120 seconds if no usable response is visible.
- For TikTok and YouTube, preserve the original search-page boundary: titles/snippets and result links only. Do not claim to have watched videos or infer unsupported video facts. Search results can establish discovery, not answer correctness or task completion.
- Raw logged-in captures and account identifiers remain outside this repository. Public observation notes contain only original redacted descriptions, source links and coded results. No private conversation URL or account name is published.

## Truth and coding

Primary references checked on October 27:

- [Apple water resistance guide](https://support.apple.com/en-us/105046), published September 17, 2026: AirPods Pro 2 with USB-C case and earbuds are IP54, unlike the Lightning variant; swimming is unsupported.
- [Sony WF-1000XM5 water-resistance manual](https://helpguide.sony.net/mdr/2963/v1/en/contents/TP1000781399.html): earbuds have IPX4-equivalent splash protection; the case is not water resistant; immersion is unsupported.

Keep the original response-state and source-boundary concepts. New outcome fields are separate:

| Field | Coding rule |
| --- | --- |
| `answerClear` | An intelligible direct answer was visible, not merely result links |
| `sourcesFound` | A relevant source/result link was visible; authority is separately noted |
| `taskCompleted` | The requested bounded comparison/claim-check artifact exists, all required facts are correct and official sources are retained |
| `artifactSaved` | A persistent user-controlled handoff/export was actually produced; an answer in chat alone is false |
| `factsCorrect` / `factsChecked` | Count checked required facts only; no inference from fluency |
| `evidenceRetained` | Distinct official supporting source links retained in the observation |
| `humanInterventions` | Extra repairs/clarifications beyond the initial submission; null if not measured |
| `elapsedMs` | Measured observation wall time, or null |
| `costUsd` | Actual attributable account charge, or null; subscriptions are not zero-cost evidence |

`NOT_RUN` and `BLOCKED` never count as completed tasks or observed wrong facts. No overall accuracy score combines these dimensions. A model's confidence is not a correctness label. Source announcements are not observations. A second coder has not yet audited this pilot.

## Reproduction

```sh
node scripts/research-round.mjs prepare /absolute/new-run.json
# Collect a real UI observation with the template emitted by prepare, then:
node scripts/research-round.mjs record /absolute/new-run.json /absolute/observation.json
node scripts/research-round.mjs summarize /absolute/new-run.json
pnpm test:round
```

The collector validates task/surface identity, unique attempts, time order, nonnegative counts, evidence requirements and unmeasured fields. Completed observations require an original observation note and supporting links; it cannot authenticate human coding or screenshots. Preserve failed attempts. Publishing results requires redaction review; the collector does not deploy the site.
